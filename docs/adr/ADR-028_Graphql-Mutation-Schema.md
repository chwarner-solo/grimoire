# ADR-028: GraphQL Mutation Schema

## Status
Accepted

## Date
2026-05-17

---

## Context

ADR-008 established GraphQL as the API layer using gqlgen (schema-first).
ADR-020 established Firebase authentication — the resolver extracts the
Firebase JWT from the Authorization header, calls `CallerIdentityPort.Identify()`,
and places the resulting `CallerID` string on every interactor request.

This ADR defines the complete mutation schema for all 27 GM interactors
(ADR-021 through ADR-027), the resolver wiring pattern, mutation response
types, and error handling.

Queries are deferred to ADR-030 — they will be driven by UI design (ADR-029).

---

## Resolver Pattern

Every mutation resolver follows this invariant:

```go
// grimoire-api/internal/resolver/mutation_resolver.go

func (r *mutationResolver) CreateGame(
    ctx context.Context,
    input CreateGameInput,
) (*MutationResult, error) {
    // 1. Extract and verify caller identity
    callerID, err := r.auth.Identify(ctx, tokenFromContext(ctx))
    if err != nil {
        return nil, ErrUnauthenticated
    }

    // 2. Build interactor request — CallerID from auth, not from input
    req := gameinteractor.CreateGameRequest{
        CallerID: callerID,
        ID:       identity.NewGameID(),
        Name:     input.Name,
        Source:   event.SourceGrimoire,
    }

    // 3. Execute interactor
    result, err := r.createGame.Execute(ctx, req)
    if err != nil {
        return nil, mapDomainError(err)
    }

    // 4. Return mutation result
    return &MutationResult{
        ID:     result.Game.GameID().String(),
        Status: result.Game.Snapshot().State,
    }, nil
}
```

**Rules:**
- `CallerID` always comes from `CallerIdentityPort.Identify()` — never from
  the GraphQL input. Clients cannot supply their own caller ID.
- IDs for new entities are generated by the resolver (or passed as input
  for idempotent clients) — never generated in the domain constructor.
- Mutation responses are `MutationResult` — identity + status only.
  Rich data comes from queries, not mutations (ADR-008).
- Domain errors are mapped to GraphQL errors via `mapDomainError()`.

## Mutation Response Type

All mutations return the same minimal type. Queries return rich data.

```graphql
# grimoire-api/schema/shared.graphql

"""
Returned by every mutation. Callers use the ID to issue a follow-up
query if they need rich data about the resulting state.
"""
type MutationResult {
  id:     ID!      # ID of the created or updated entity
  status: String!  # current lifecycle state (e.g. "new", "active", "archived")
}
```

## Error Mapping

Domain errors are mapped to GraphQL errors in `grimoire-api/internal/resolver/errors.go`.
GraphQL errors carry an `extensions.code` field for structured client handling.

```go
func mapDomainError(err error) error {
    switch {
    case errors.Is(err, sharedinteractor.ErrUnauthorized):
        return gqlerror.Errorf("UNAUTHORIZED: caller is not authorized")

    case errors.Is(err, gameentity.ErrInvalidGameState):
        return gqlerror.Errorf("INVALID_STATE: game is not in the required state")

    case errors.Is(err, campaignentity.ErrInvalidCampaignState):
        return gqlerror.Errorf("INVALID_STATE: campaign is not in the required state")

    case errors.Is(err, campaignentity.ErrNoCharacters):
        return gqlerror.Errorf("PRECONDITION_FAILED: campaign has no characters")

    case errors.Is(err, narrativeentity.ErrCycleDetected{}):
        return gqlerror.Errorf("CYCLE_DETECTED: prerequisite would create a cycle")

    case errors.Is(err, narrativeentity.ErrPrerequisiteNotMet{}):
        return gqlerror.Errorf("PRECONDITION_FAILED: beat prerequisites are not met")

    // Interactor-level not-found errors
    case isNotFound(err):
        return gqlerror.Errorf("NOT_FOUND: entity does not exist")

    // All other errors — do not leak internal details
    default:
        return gqlerror.Errorf("INTERNAL: an internal error occurred")
    }
}
```

## Authentication Middleware

```go
// grimoire-api/internal/middleware/auth.go

// AuthMiddleware extracts the Firebase JWT from the Authorization header
// and places the raw token in the request context.
// CallerIdentityPort.Identify() is called by the resolver — not here.
// This keeps the middleware thin and the identity resolution at the
// correct boundary (resolver = port adapter).

func AuthMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        token := strings.TrimPrefix(
            r.Header.Get("Authorization"), "Bearer ")
        ctx := context.WithValue(r.Context(), tokenKey{}, token)
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}

func tokenFromContext(ctx context.Context) string {
    token, _ := ctx.Value(tokenKey{}).(string)
    return token
}
```

## Consequences

- All 27 GM interactors are reachable from one GraphQL endpoint
- `CallerID` is never client-supplied — always resolved from Firebase JWT
  by `CallerIdentityPort.Identify()` at the resolver boundary
- Mutation responses are intentionally minimal — `id` + `status` only.
  Rich data comes from queries (ADR-030), not mutations
- `mapDomainError()` ensures internal error details never leak to clients
- gqlgen generates typed resolver interfaces — missing mutations are
  compile errors, not runtime surprises
- Queries are explicitly absent — deferred to ADR-030 after UI design
- Subscriptions (`entityRevealed`, `sessionStarted`) are deferred to
  the Player app ADR — not needed for the GM web UI

## Breaking Changes from ADR-008 Sketch

ADR-008 included a rough mutation sketch. This ADR supersedes it:
- `addNarrativeElement` → retired, replaced by `createMasterBeat` etc.
- `startSession` → split into `startFirstSession` and `startNewSession`
- `endSession` → retained, gains `sessionId` and `notes` fields
- All inputs now have dedicated `Input` types — no inline arguments
- `CallerID` extraction is explicit in the resolver pattern
